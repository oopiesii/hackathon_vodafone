# Контекст і статус рішень

## Мета

Допомогти комунікаційній команді Vodafone помічати репутаційні сигнали, бачити причини та докази й готувати короткий бриф для дії. Погоджені два представлення: стрічка й інциденти. Прогноз майбутньої кризи не є перевіреною можливістю.

## Актуальні рішення

| Рішення | Статус і підстава |
| --- | --- |
| Спілкування й документація українською | Пряма вказівка користувача |
| Першим реалізувати тестовий Telegram-модуль, пости й коментарі | Нове пряме доручення; скасувало попередню паузу на код |
| Адмін задає workflow, credentials, активність модулів, створює обмежені посилання | Пряма вказівка користувача |
| Зберегти каркас Claude та виконати root-частину перенесення/запуску | Пряма вказівка; каркас імпортовано зі scratchpad без його `.env` і тестових користувачів |
| TypeScript/Hono/Better Auth/Kysely, React, PostgreSQL, NATS; Python/Telethon та processor | Реалізований стек на підставі доручення зберегти каркас |
| Використати дизайн із GitHub | **Замінено 2026-09-19.** Пряма вказівка користувача: повний редизайн у строгому діловому стилі на зразок shadcn/ui, червону гаму зберігати не потрібно. Оригінал `vodafone-monitor/vodafone-monitor` збережено без змін як історичний макет |
| `hire.qpon` має вести виключно на Vodafone | Пряме доручення на перенесення домену; стан розгортання в STATUS |
| AES-256-GCM, автоматична реєстрація сесії з CLI та додатковий імпорт, одна сесія на канал, правила замість LLM | Інженерні рішення тестової реалізації, не окремі відповіді команди |
| Polling 30 с, історія 7 днів для нового каналу, модуль початково off | Змінювані технічні defaults; не погоджений SLA чи гарантоване покриття |

Раніше обговорені Go/Rust, один backend із api/worker та черга тільки в PostgreSQL залишаються історичними кандидатами. Вони не є інструкцією переписувати чинний TS-каркас. NATS уже частина інтегрованої реалізації; PG/outbox/receipts забезпечують відновлення обробки.

## Незмінні вимоги

Реальні дозволені джерела; не зберігати профілі авторів; факт → цитата → оригінал; невідомі факти не домислювати. Повторення тексту не є незалежним підтвердженням. Затримку збору/аналізу, хибні спрацювання та неповне покриття показувати чесно. Історію або синтетичну перевірку не називати live. Не заявляти точність, risk score чи KPI без вимірювання.

## Джерела

Telegram обрано для першого модуля. За прямим дорученням користувача 2026-09-19 авторизовано другу сесію та явно імпортовано 66 публічних broadcast-каналів: 20 на Telegram 1 і 46 на Telegram 2. Для цього додано серверний ідемпотентний імпортер `scripts/import_telegram_sources.py`; він обробляє `FloodWait`, не зберігає секрети й не є автоматичним discovery. Ще 15 наданих URL або не мають чинного username, або ведуть до непідтримуваних груп; їх не позначено активними. Додане раніше джерело є публічною супергрупою, яку поточний collector каналів відхиляє (`PublicBroadcastRequired`). Пізніше додано окремий публічний канал #2: один пост отримано й відсіяно rules-v1; це не перевірка якості або повного сценарію коментарів. Умови Telegram перевірено 2026-09-19; обмеження та посилання в [TELEGRAM.md](TELEGRAM.md). Наявність публічного каналу не доводить права на AI-використання або збереження коментарів. Поточний processor не використовує LLM.

GDELT, прямі RSS/API медіа та офіційні новини операторів лишаються кандидатами для ширшого MVP. Історичні спостереження щодо rate limit GDELT і некомерційних умов Google News RSS не є новою перевіркою й не дають дозволу на production. Snapshot/replay реальних матеріалів обговорено як резерв, конкретного випадку немає.

## Що ще відкрите

У команді 7 учасників, імена/навички/доступні години невідомі. 1–2 дні — попередня оцінка; 6 годин в умовах не підтверджує фактичний дедлайн. Потрібні роль для пітчу, реальний випадок, незалежна ручна перевірка, обсяг конкурентного аналізу й інцидентів, LLM-провайдер/бюджет та підтверджені права на дані для AI.

[QUESTIONS.md](QUESTIONS.md) зберігає нумерацію запитань і часткові відповіді з нових доручень. [ARCHITECTURE.md](ARCHITECTURE.md) описує реалізовані контракти, а не колишні припущення.

## Останнє уточнення: Sources та увесь вхід

Користувач попросив окрему вкладку Sources із перемикачами й налаштуваннями сервісів, бачити весь вхід до фільтрації та підготувати два акаунти. Реалізовано Sources, операторський `/inbox` і два account slots. Обидві сесії авторизовані й online; явний список користувача розподілено між ними через контрольований серверний імпортер. Користувач додав власне тестове джерело, але воно є супергрупою замість каналу; підтримка окремих груп ще не реалізована. Це не змінює вимоги мати окремий реальний сценарій хакатону. Пошук нових джерел нейронкою обговорено як можливість, але не реалізовано; імпорт працює лише з прямо переданими адміністратором адресами.

Користувач відкинув обов’язковий ручний імпорт після CLI-входу. `scripts/create_session.py` тепер сам зберігає сесію та API-доступ у системі. Старий файл `dump-env` містив лише StringSession; сесію відновлено без нового OTP, відсутній API-доступ доповнюється окремо.

Новий запит: користувач просить оцінити прогалини Telegram-модуля й механіку bulk-add/join, очищення/релевантності, коментарів і реакцій, адаптивного стеження 2–24 дні та аналітики в dashboard. Пропозиція — [TELEGRAM_NEXT.md](TELEGRAM_NEXT.md); thresholds, cadence, LLM і межі lifecycle ще не погоджені. Реальний канал #2 уже читається; група #1 поки відхиляється.
