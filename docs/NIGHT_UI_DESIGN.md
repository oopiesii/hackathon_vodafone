# Дизайн нічного дашборда

Підстава: [PLAN_NIGHT](PLAN_NIGHT.md), §3 та §7; пряме доручення на нейтральний діловий стиль.

Головне — статус бренду й назва проблеми; поруч шість вимірювань. Далі список сигналів займає 7/12 ширини, погодинний ряд — 5/12. Реакції, джерела й поширення — три рівні колонки. Мережа та гроші лежать нижче, оскільки це слоти/припущення. На телефоні статус перший, показники по два, решта послідовно. Основне вирівнювання — ліворуч, числа в порівняльних списках праворуч.

Палітра: поверхні `#ffffff`/`#0c0c0e`, текст `#09090b`/`#fafafa`, межі `#e4e4e7`/`#27272a`, дані `#2a78d6`/`#3987e5`; сірий `#a1a1aa`/`#52525b` позначає контекст, не окрему категоріальну шкалу. Стани мають чинні текстові позначки й токени. Шрифт — встановлений Vodafone, далі локальний Inter; розміри тільки `--f-*`.

Форма перед кольором: поточний показник → числова плитка; часовий ряд → стовпчики зі складанням «мережа / інші теми»; реакції → горизонтальна смуга + підписані числа; джерела → список смуг. Один синій акцент відповідає вимозі плану, сірий контекст не конкурує зі статусами. Синтетичні ряди лише в `tests/fixtures`; застосунок отримує дані виключно з API.

Валідатор dataviz: окремий акцент проходить світлу й темну тему. Початкова спроба перевірити контекстний сірий як категоріальний колір була методологічно хибна (chroma floor); виправлено область перевірки, а не правила валідатора. Смуга реакцій — семантичні стани з прямими текстовими підписами, не категоріальна палітра.

Перевірки й знімки: `scripts/check_dashboard_browser.mjs`, локальні `artifacts/night-dashboard`. Детальні результати та ворота — у [STATUS](STATUS.md).

## Інтеграція слотів та операторських станів

WP3: клікабельні синтетичні регіони → вишки → деталі, позначка демо на кожному рівні. Реальний стан мережі явно невідомий. Контракти подій network/social — окремі JSON Schema; ні демо, ні сценарії калькулятора не записуються в БД/NATS. Threads і X у Sources позначені «не підключено», цикл стеження описано як майбутній.

WP4: калькулятор спирається на 14,9 млрд грн / 4 344 години та ARPU 154 грн за [публікацією Інтерфакс-Україна від 28.08.2026](https://interfax.com.ua/news/telecom/1196790.html), сторінку перевірено під час реалізації. Втрати, відтік і витрати реагування — сценарії з припущеннями й способом перевірки. Некоректне/порожнє поле не перетворюється на нуль.

WP2: admin запускає позачерговий цикл, бачить окремі стани Telegram/RSS; інші ролі оновлюють лише показники. Поки запит у черзі, UI опитує стан кожні 2 секунди, показники — після зміни стану; звичайний цикл — 5 хв. Неповні місячні агрегати замінено явним очікуванням без нульових псевдовимірювань; перевірка завершення кожні 3 секунди.

WP8a UI: heartbeat, режим, модель, ліміт і дозволи джерел у Sources. Зміна дозволу вимагає явної дії адміністратора; увімкнення — підстави. RSS без дозволу заблокований; Telegram автоматично не вмикається.

Повторний рендер: 1440/768/390, світла/темна; калькулятор (включно з арифметикою 2 год × 50% і порожнім полем), мережеві переходи й повернення, Sources, 7 днів → метрика → доказ → назад. Вісім станів дашборда, зокрема viewer, перерахунок і перебіг збору, перевірено браузером. Виявлене переповнення панелі перебігу на 390 px виправлено прив'язкою правого краю; цільовий повтор у всіх шести розмірах/темах пройшов, знімки до/після переглянуто.

Другий погляд: виправлено нульову смугу, яка раніше мала ненульову довжину; показано бренд кожного сигналу; кількість поширень більше не підписана кількістю матеріалів; відмінювання винесено в спільну функцію. Реальні вимірювання перевірятимуться окремо після релізу — синтетичні браузерні сценарії їх не доводять.
