## Перевірено

- `npm ci`, `npm run typecheck`, `npm run build`; збірка Docker Node/Python.
- Міграції й повторний запуск bootstrap без зміни наявних таблиць; окремі облікові ролі PostgreSQL.
- **12 тестів пройшли:** 2 перевірки правил/маскування + 10 інтеграційних сценаріїв, включно з автоматичною реєстрацією, завершенням API-доступу та відновленням після збою без нового OTP. Окрема БД `ufv_checks`, справжні Hono/Better Auth/PostgreSQL/NATS, Telegram замінено контрольованими об'єктами.
- TS encrypt → Python decrypt; секрети не повертаються; повторні raw/event/process не створюють дублікати; вкладений контекст, спам, реклама, редагування/видалення; cursor після рестарту, FloodWait, вимкнений модуль.
- 401 без сесії, 403 на admin для viewer/чужий Origin, posts-only/summary scope, заборона доступу до іншого workflow, відкликання посилань.
- NATS JetStream outbox → processor; відновлення API після завершення його PostgreSQL-з'єднань. Знайдену необроблену idle pool error виправлено, повторна перевірка пройшла.
- Chromium/Playwright локально й через production HTTPS: вхід, React-навігація, адмін-консоль, reprocess з обмеженою DB-роллю, розміри 320/768/1024/1440, темна тема, secure HttpOnly-cookie; без runtime JS/CSP errors.
- Production: сесія Better Auth пережила заміну API-контейнера; scoped link відкрився в окремому браузерному контексті, fragment прибрано, відкликання завершило доступ. Heartbeat обох worker видно в адмінці.
- Окремо на тестовій БД перевірено запис raw/outbox роллю ufv_collector та обробку/запис core роллю ufv_processor з production grants.
- Caddy config validation, HTTPS 200, API health 200, feed 401 без входу, retired hire subdomain 404, основний Warblan health 200.

Це перевірки працездатності, не оцінка точності й не повний Telegram acceptance. Реальне підключення акаунта та доставку одного поста перевірено; це ще не повний сценарій із тематичними матеріалами й коментарями.

## Не виконано / потрібні вхідні дані

- **Канал уже читається, окрема супергрупа ще не підтримується.** Потрібно завершити live acceptance на тематичних постах/коментарях та визначити розширення підтримки груп. Покриття реальних коментарів і фактичну затримку ще не перевірено.
- Права на збір/показ конкретних матеріалів і коментарів має встановити команда. Telegram-контент не передається в LLM; актуальні обмеження наведено в TELEGRAM.md.
- Реальний наскрізний сценарій хакатону, ручна вибірка якості, інциденти, AI-бриф, аналіз конкурентів, KPI та прогнозування ще не готові.
- Не підтримуються web SMS/QR-авторизація Telegram, приватні канали, OCR/аудіо, автономний auto-join/discovery collector, горизонтальні репліки collector, повне відновлення старих офлайн-редагувань/видалень.
- Немає автоматичного backup PostgreSQL або повної системи виявлення персональних даних всередині довільної прози; маскуються типові контакти, профілі авторів не збираються.
- Часткові відповіді команди зафіксовано в QUESTIONS; точний дедлайн, навички/власники задач і людина для ручної перевірки ще невідомі.
