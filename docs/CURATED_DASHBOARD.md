# Семантичний відбір головного дашборда

Підстава: пряма скарга користувача 19.09.2026 на політичний шум у метриках і переходах, відсутність Vodafone та незрозумілий розрахунок реакцій. Користувач також прямо попросив посилювати червоний акцент для великих значень. Це локальний виняток із нейтральної дизайн-системи, а не зміна всієї палітри.

## Відбір

Коренева причина: `/analysis` читав Gemini-результати, але `/` і `/feed` продовжували використовувати словниковий `core.mentions`. Зокрема, політичні записи 53249, 1463, 64387, 64380, 74214 були прийняті правилами й відсіяні Gemini; новий 111788 ще не мав AI-результату.

Міграції **0020–0022** додають `core.semantic_classifications`, `core.curated_items`, `core.curated_visible_items`, `core.curated_daily_rollups`. Старі raw/mentions і міграції не переписуються. API не отримує прямий доступ до raw. Одна ефективна класифікація використовується у dashboard, feed, деталях і scoped shares.

- Після завершеного AI-прогону workflow переходить на семантичний відбір: нові чи застарілі записи мають `pending`, без повернення до старих словникових правил. Workflow без завершеного прогону зберігає режим правил із явним підписом.
- Береться останній завершений аналіз конкретного запису. Перевіряються версія тексту, видалення, версії всіх переданих контекстів та поява раніше відсутнього батьківського повідомлення.
- Актуальні `relevant` → `accepted`; `review` → окремий операторський розгляд; unrelated/spam/ad → rejected. Тестові джерела зі scope прогону виключаються зі статистики.
- Ручне рішення має пріоритет для тієї самої версії. Видалення чи нова версія скасовують старе рішення. Дані тестових джерел не стають реальними показниками через ручне прийняття.
- Основні семантичні метрики включають лише accepted. Адміністратор бачить відсіяне окремим переходом, увесь вхід — у Inbox. Viewer і shares отримують тільки accepted у межах свого scope.
- Тональність і тема беруться з актуального AI-результату; негативний аспект також враховується. Основний бренд — Vodafone, інакше Kyivstar/lifecell/telecom. Порівняння з кількома брендами поки не має окремих незалежних лічильників для кожного аспекту.
- У стрічці є підпис AI, короткий модельний висновок, пояснення та дослівна цитата з самого запису; повний контекст відкривається з перевіркою прав. Модельні URL не використовуються.

Місячні семантичні агрегати обчислюються на запит із поточних рішень. Вони не залежать від часткової інвалідації старої `daily_rollups`. 0022 утримує перевірку актуальності окремо для кожного потенційно видимого ID: на реальній базі контрольний count місячного view зайняв близько 0,10 с. Це час цього SQL-запиту, не SLA всього API.

Додано явний перехід **«Vodafone: згадки за 7 днів»**. Під час перевірки він повертав два матеріали:

- 17.09: [Babel про фінансування мережі й 5G](https://t.me/babel/89794), mention 47170.
- 18.09: [Vodafone про відновлення базових станцій](https://t.me/VFUkraine/1472), mention 28650.

Обидва не входили у rolling 24h під час перевірки. Відсутність нових прийнятих згадок не означає відсутності проблем або відсутності непроаналізованого входу. UI показує cutoff разового прогону й кількість pending. Безперервний AI-consumer цим виправленням не додається.

## Реакції та сигнали

Джерело реакцій — агреговані Telegram-лічильники останнього збереженого спостереження кожного видимого матеріалу. Ідентичності людей не збираються. Сума не є кількістю унікальних абонентів.

- Негативні emoji: 👎 😡 🤬 🤮 💩 🤡. Частка = ця сума / усі реакції.
- Іронічні 🤣 😁 😈 та сумні 😢 💔 😭 показуються окремо; решта не називаються автоматично позитивними. Реакція на новину не доводить ставлення до оператора.
- Пороги червоного акценту **25% / 50% / 75%** діють лише за **≥20 реакцій на ≥3 матеріалах із доступними лічильниками**. Вибрано агентом для демо за запитом користувача; точність/кризова цінність порогів не виміряні. Є текстові рівні й значок, без миготіння.
- Критичні матеріали — евристика високого сигналу за 24 години: негативний тематичний матеріал із ≥3× медіани до 30 постів джерела, за наявності щонайменше 10 виміряних постів; або ознаки збою в ≥3 джерелах за 2 години. Кілька джерел можуть бути передруками. Популярна позитивна новина сама по собі не стає кризою.
- Для критичних матеріалів акцент посилюється на **1–2 / 3–4 / ≥5**. Це ступені уваги, не прогноз чи ймовірність кризи.

UI читає фактичні налаштування watch-policy; за замовчуванням active — 5 хв, cooling/blocked — 1 год, sleeping — 6 год. Archived/paused не перевіряються за розкладом. Черга джерел і FloodWait можуть збільшити інтервал. У картці видно діапазон дат збережених спостережень; у «Контекст і доказ» — історію та наступний watch-check. Перемальовування dashboard раз на 5 хвилин не гарантує нового Telegram-вимірювання чи нового LLM-аналізу.
