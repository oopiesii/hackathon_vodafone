# API-міст для відкату після 0030

Підстава: незалежний review виявив, що API зі стану `main 4ff95b9` сумує `curated_daily_rollups` без перевірки покриття. До 0030 view обчислює поточні результати безпосередньо. Після 0030 він читає фізичні покоління та приховує dirty-джерела. Повернення старого image тоді показало б неповний місяць як повний, аж до неправдивого нуля.

Цей окремий bridge залишає поточний API/UI та додає перевірку лише до місячного читання. Якщо `core.dashboard_rollup_state` існує, покриття всіх джерел обраного workflow й агрегати читаються **одним SQL statement, в одному MVCC snapshot**. Dirty, відсутній state або `generated_at=null` дають HTTP **503** із поясненням: «Місячні агрегати перераховуються. Спробуйте оновити сторінку пізніше». Чисте порожнє покоління повертає звичайний порожній набір. Права accepted/review та межі workflow збережено.

До 0014 виконується чинний curated-запит. Наявність state перевіряється знову після нього: якщо міграція встигла додати state, неперевірені рядки відкидаються і виконується атомарний шлях. Рекурсії немає; відсутність state не кешується. Помилки SQL або прав не переводять запит на обхідний шлях.

Bridge призначено спершу розгорнути **лише як API image** й зберегти як попередній image повного нічного релізу. SQL-міграцій, змін processor, collectors, deployment script, налаштувань або Telegram LLM-дозволів у коміті немає. Коміт сам по собі не означає розгортання. Чинний UI показує українську помилку; якщо в браузері вже був успішний зріз, його попередній кеш може залишатися поруч із повідомленням та часом зрізу. API не повертає частковий новий результат як успішний.

## Перевірки

```sh
npm run typecheck
npm run build
UFV_TEST_ENV=/tmp/ufv-rss-checks-env.json node --test tests/monthly-bridge.test.mjs
```

Захищений конфіг читається без виводу значень; runner відмовляється працювати, якщо назва БД не `ufv_checks`. Інтеграція працює однією транзакцією з повним rollback, без TRUNCATE, без зовнішніх HTTP/Telegram/LLM-запитів. Перевірено реальну роль `ufv_api` на схемі 0030+0031: неповні й відсутні покоління, нульовий чистий результат, accepted/review, незалежний dirty-workflow, HTTP 503 через Hono. Гілку до 0014 перевірено симуляцією відсутньої назви relation всередині SAVEPOINT; окрему стару БД не розгортали. Додатковий тест моделює завершення міграції між першим probe і legacy-запитом: `false → true → dirty` повертає 503.

Результат: TypeScript typecheck і повна збірка пройшли; **5 цільових тестів PASS**. Приклад результатів синтетичний і не потрапляє до production. Production не змінювався цим потоком; розгортання й післярелізна перевірка належать root.
