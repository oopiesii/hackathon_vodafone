# RSS: колектор, джерела та production

Оновлено 2026-09-19. Пряма вказівка користувача: додати максимально можливу кількість знайдених RSS, увімкнути збір і перенести зміни з робочих гілок у production. Реалізацію інтегровано разом із Telegram-інкрементом `c01f020`; робоча гілка — `feat/rss-collector`, worktree `/opt/ufv-worktrees/rss-collector`. Код перенесено в `/opt/ufv` без reset/clean та без зміни чужого Git-індексу. Push не виконувався.

## Що працює

- https://hire.qpon/sources/rss — адміністратор бачить стан модуля/джерел, перемикачі, останній успішний збір, наступну спробу, помилки, лічильники, умови використання. Додавання до 50 HTTPS RSS/Atom URL списком із workflow та підставою використання.
- https://hire.qpon/inbox — усі отримані й очищені матеріали, включно з відхиленими; доступ admin/analyst. https://hire.qpon/ — тематичні матеріали. Viewer не отримує керування чи весь вхід.
- Автономний `collector-rss`: читає конфігурацію з PostgreSQL, не потребує Telegram-сесій чи LLM-ключа. Типовий інтервал 300 секунд; ліміти, помилки та Retry-After відкладають повторну спробу.
- Отримуються тільки заголовок і явно наданий RSS/Atom summary. Немає обходу повних статей, фото, авторських профілів, коментарів чи лічильників переглядів. Авторські поля XML не зберігаються; звичайні контакти в тексті маскуються. Summary технічно обмежений 2400 символами, заголовок — 600; `content_scope=excerpt`.
- `published_at` і `edited_at` зберігаються лише за наявності відповідних дат; невідома дата не підмінюється fetched_at. Час першої появи у feed та час події невідомі. Початкові матеріали можуть бути історичними — це не вимірювання live latency і не повний архів.

Підстави, URL умов і дата перевірки збережені у `services/collector-rss/catalog.json` та конфігурації БД. Це оцінка для поточного показу коротких анонсів із посиланнями, не загальний дозвіл на повні тексти, навчання LLM або повторну публікацію всього архіву.

Ще **5 стрічок** збережено вимкненими: ITC, AIN, dev.ua, Інтерфакс «Телеком» та «Останні новини». ITC/AIN обмежують копіювання письмовою згодою, виняток — нерегулярне цитування до 5%; dev.ua вимагає згоду адміністрації; Інтерфакс обмежує відтворення/поширення та заявляє щонайменше 15 хв затримки відкритої частини. Не підмінювати ці умови доступністю XML. Bulk-import не знімає вже встановлене блокування. Після отримання прав зміну статусу й підстави потрібно внести окремо; окремого UI для погодження ліцензії ще немає.

Перший production-цикл: 230 записів, **213 різних URL**, 4 матеріали accepted правилами. Це спостереження на момент запуску, не метрика точності. Кілька стрічок одного видавця не є кількома незалежними джерелами доказів.

## Контракти та надійність

`core.sources(kind=rss)` + `core.rss_sources` — конфігурація API. `raw.rss_state` — спостережений стан колектора: validators, розклад, помилки та lease token. `core.rss_status` — вузьке read view для API. Нові поля `source_kind`, `title`, `content_scope` доступні через `core.incoming_items`.

`fetch → parse/normalize → raw.items + raw.item_versions + raw.outbox` в одній транзакції → NATS `raw.item.created` v1 → спільний processor → `core.mentions`/receipts → API. Подія містить тільки ID, час і правильний `source_kind`; кожен publisher вибирає outbox свого типу. Redis/Kafka і окремий аналізатор для RSS не додаються.

GUID (або URL) визначає стабільний source_item_id; повторний GUID/URL не створює новий матеріал. Редагування тексту чи метаданих збільшує версію. HTTP 304 не створює подій. Зникнення статті з обмеженої RSS-стрічки не означає видалення. URL/точний текст допомагають позначати дублі між стрічками; семантичне виявлення передруків не реалізоване.

Умовні HTTP-запити ETag/Last-Modified, backoff, Retry-After, 3 паралельні джерела. Адреси тільки HTTPS; перед кожним redirect перевіряються схема/порт, DNS-адреси тільки публічні, TCP з'єднання закріплено за перевіреною IP з TLS SNI оригінального hostname. Немає доступу до localhost/private/metadata через feed URL або redirects. Ліміт XML 4 MiB, 500 entries, DTD/entities відхиляються. HTML не виконується й не вставляється у DOM.

Lease token не дозволяє старому worker записати результат після повторного захоплення задачі. Після HTTP повторно перевіряється конфігурація. Вимкнення зупиняє наступні запити; вже розпочатий HTTP-запит може завершитися. Втрата події компенсується DB catch-up processor.

## Аналіз

RSS використовує `rss_classification.py`: явні бренди/ознаки телеком-зв'язку. «Мережа магазинів», «тариф на світло», загальна «підтримка» не є достатніми підставами. Текст і пояснення рішення видно в Inbox; адміністратор може виправити рішення. Це правила, не LLM, не прогнозування кризи й не виміряна точність. Повний текст може містити релевантність, якої не видно в короткому RSS-анонсі.

Відтворення: `pip install -r services/collector-rss/requirements.txt`, `npm run build`, міграції й grants через `deploy/bootstrap.py`; `DATABASE_URL=... python scripts/seed_rss.py --enable` для явного імпорту каталогу. Скрипт не переписує наявні source settings. Не передавати реальний DSN у CLI/логи: використовувати захищене оточення. Тести: `UFV_TEST_ENV=/protected/ufv_checks.json python -m pytest tests -q`; браузер `scripts/check_rss_browser.py`. Синтетичні дані лише у `ufv_checks`.
